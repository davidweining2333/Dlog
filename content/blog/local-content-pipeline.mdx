个人站点很容易在“后台、数据库、富文本编辑器”里越走越重。对许多写作者来说，更合适的起点其实是：**文章就是文件，仓库就是 CMS**。

## 为什么选择本地 MDX

Markdown 已经足够表达大多数叙事；MDX 则在需要时插入真实组件。更重要的是，文件形态带来三件免费的好处：

- Git 历史完整记录每一次修订；
- 离线也能写作，预览与生产使用同一套渲染；
- 部署即发布，没有额外内容服务需要维护。

Dlog 用 `gray-matter` 解析 front matter，用 `next-mdx-remote/rsc` 在服务端渲染正文。列表页只依赖元数据，详情页再渲染全文，构建成本保持可控。

## Front matter 作为最小契约

一份可靠的文章元数据，至少应包含：

```yaml
title: "标题"
description: "摘要"
date: "2025-03-02"
tags:
  - Next.js
published: true
```

校验逻辑宁可严格也不要静默失败。缺字段、日期非法、标签为空时直接丢弃该条目，比把半成品页面暴露给读者更安全。

## 从正文提取结构

阅读时长、目录和相关推荐都不需要作者手工维护：

1. 去掉代码块后统计中英文字符，估算阅读时间；
2. 扫描二级/三级标题生成 TOC，并为锚点生成稳定 slug；
3. 用标签交集计算相关文章，再按时间加权排序。

这些派生数据在构建时计算一次，读者侧几乎零成本。

## 搜索与筛选保持客户端轻量

个人博客的体量很少需要搜索引擎。把已发布的文章元数据一次性交给客户端，用标题、摘要和标签做包含匹配，已经足够顺手。若未来文章上千，再考虑倒排索引或 Pagefind 也不迟。

## 内容系统也是产品

把写作管线当成产品的一部分来打磨，会改变你写文章的方式：标签开始有意义，摘要会更克制，修订也更敢于发生。工具不替你思考，但它会让正确的事更容易发生。
